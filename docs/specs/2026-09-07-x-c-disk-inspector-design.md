## 1. 产品目标

“X C盘巡检官”用于解释 C 盘空间被什么占用，并在明确展示风险和后果后执行保守清理。应用必须帮助用户理解目录，而不是只给出一串路径或把“大文件”直接等同于“垃圾”。

成功标准：

1. 用户能看到磁盘总量、已用、剩余和可访问文件的统计总量。
2. 用户能看到主要目录、重点子目录和大文件，并了解其对应软件、用途、完全删除的后果、风险与建议操作。
3. 默认操作不会删除模型、项目、聊天数据、个人文件、虚拟磁盘或 Windows 关键组件。
4. 清理前提供预览，清理后提供逐项结果、失败原因和释放空间。
5. 程序可打包为单文件 Windows EXE，并提供完整源码与测试。

## 2. 产品名称与视觉设计

应用名称为“X C盘巡检官”。

视觉语言：

- 深色石墨背景，减少长时间扫描时的视觉疲劳。
- 青蓝色用于正常状态和扫描轨迹，橙色用于需要判断的项目，红色只用于不可逆或高风险动作。
- 首页主视觉是磁盘雷达环：扫描期间沿圆周运动，完成后变为容量环。
- 图标由字母 `X`、磁盘圆环和一道扫描光束组成，不使用常见的盾牌、扫帚或火箭图形。
- 动效必须克制：页面切换淡入、扫描光束循环、数字平滑增长；支持系统“减少动画”设置。
- “关于”页、报告页脚和应用元数据中展示作者信息。

## 3. 页面结构

### 3.1 首页

- C 盘容量环：总容量、已用、可用、已用百分比。
- 三个主要操作：“开始扫描”“载入上次报告”“安全清理”。
- 扫描期间展示当前目录、文件数量、累计容量、耗时和取消按钮。
- 首次打开时不自动扫描，不自动申请管理员权限。

### 3.2 扫描结果

- “主要占用”按一级目录和根目录文件汇总。
- “重点目录”展示目录、容量、对应软件、用途、删除后果、风险等级、建议。
- “大文件”默认展示大于 500MB 的文件，可调整阈值。
- 支持按容量、风险、软件、建议清理状态筛选。
- 每个可处理项目左侧提供复选框；列表顶部提供“全选建议项”和“取消全选”。
- “全选建议项”只选择当前筛选范围内通过安全允许列表的项目，不选择高风险、个人数据或系统关键项目。
- 被禁止自动清理的项目显示禁用复选框和禁止原因，不能通过全选或界面状态绕过。
- 页面底部固定显示已勾选项目数量、预计容量、最高风险等级和“一键删除已选项”按钮。
- 逻辑文件大小与磁盘已用空间存在差异时明确提示，不伪装成精确可回收空间。

### 3.3 安全清理

- 分为“建议清理”“需要确认”“仅提供操作指导”三组。
- 每项显示路径、预计大小、选择状态、风险、清理后果和恢复可能性。
- 默认只勾选安全规则允许的项目。
- 用户可以逐项勾选，也可以使用“全选建议项”；切换筛选条件不会悄悄改变已有选择。
- 点击“一键删除已选项”后，程序重新计算并展示最终清单；用户确认一次后按清单顺序执行。
- 最终确认窗口明确列出不可恢复项目，并要求用户单独勾选“我理解回收站清空后无法恢复”，否则回收站不会被处理。
- 一键删除过程中可以停止后续项目；正在删除的单个文件操作不会被强制中断。
- 执行前显示最终清单并进行一次明确确认。
- 清理后展示成功、跳过、失败、实际释放容量和需要重启的项目。

### 3.4 系统优化建议

- 页面文件只做检测和建议，不纳入默认一键清理。
- Windows 组件存储只调用官方 DISM 能力，不直接删除 `WinSxS` 或 `Windows\Installer`。
- 已安装软件只提供“打开系统卸载页面”，不直接删除安装目录。
- WSL、Docker 虚拟磁盘只提供官方清理/压缩说明，不直接删除 VHDX。

## 4. 扫描引擎

扫描只读取文件系统元数据，不读取文件内容。

规则：

1. 单遍遍历并累计目录容量，避免对每个目录重复递归。
2. 默认不跟随重解析点、目录联接和符号链接，防止循环及跨盘统计。
3. 无权限访问的目录记录为“无法访问”，不中断整个扫描。
4. 支持取消；取消后保存明确标记为“不完整”的报告。
5. 最大文件使用有界集合保存，避免在内存中保留全部文件记录。
6. 界面通过批量进度更新，不为每个文件刷新 UI。
7. 扫描结果包含时间戳、程序版本、规则库版本和管理员状态。

## 5. 软件与目录识别规则

内置可扩展 JSON 规则库。每条规则包含：路径模式、软件名称、用途、完全删除后果、风险等级、建议动作、是否允许自动清理。

首版覆盖：

| 目录/文件 | 对应软件或系统 | 完全删除的后果 | 默认建议 |
|---|---|---|---|
| `C:\pagefile.sys` | Windows 虚拟内存 | 直接删除不可行；错误关闭可能导致内存不足、程序崩溃 | 仅检测并指导设置 |
| `C:\$Recycle.Bin` | Windows 回收站 | 已删除文件无法再从回收站恢复 | 需要确认，可清理 |
| `%LOCALAPPDATA%\Temp` | Windows 与应用临时文件 | 正在使用的文件会跳过；部分应用可能重新生成缓存 | 默认仅选择 7 天前文件 |
| `%LOCALAPPDATA%\CrashDumps` | Windows 应用崩溃转储 | 失去历史崩溃诊断材料 | 建议清理 |
| `%LOCALAPPDATA%\wsl\*\ext4.vhdx` | WSL 发行版 | 删除会丢失整个 Linux 系统及其中数据 | 禁止自动清理 |
| `%LOCALAPPDATA%\Docker\*` | Docker Desktop | 删除可能丢失镜像、容器、卷及构建缓存 | 仅提供官方清理指导 |
| `%LOCALAPPDATA%\OmniVoice\hf_cache` | OmniVoice / Hugging Face 模型 | 模型需重新下载，离线功能不可用 | 默认保留，可单独选择模型缓存 |
| `%LOCALAPPDATA%\com.debpalash.omnivoice-studio\project\.venv` | OmniVoice Studio Python 环境 | 应用运行失败，需重新安装依赖 | 默认保留 |
| `%LOCALAPPDATA%\JianyingPro` | 剪映专业版 | 可能丢失缓存、草稿引用或下载组件 | 仅识别并引导应用内清理 |
| `%APPDATA%\TRAE SOLO CN` | TRAE SOLO CN | 可能丢失扩展、虚拟机工具、缓存及本地状态 | 默认保留，细分缓存后再建议 |
| `%APPDATA%\Tencent` | 腾讯系软件 | 可能包含聊天文件、图片、日志及缓存 | 默认保留，只标记已知缓存 |
| `%USERPROFILE%\.bun` | Bun | 依赖缓存需重新下载 | 可选开发缓存清理 |
| `%LOCALAPPDATA%\npm-cache` | npm | 包需重新下载 | 可选开发缓存清理 |
| `%LOCALAPPDATA%\pnpm-cache` | pnpm | 包需重新下载 | 可选开发缓存清理 |
| `%USERPROFILE%\.cache` | 多种开发/AI 软件 | 可能造成模型或依赖重新下载 | 默认不整体清理，按子目录识别 |
| `C:\Windows\WinSxS` | Windows 组件存储 | 手工删除会破坏更新、修复和系统组件 | 禁止直接删除 |
| `C:\Windows\Installer` | Windows Installer 缓存 | 手工删除会导致修复、更新或卸载失败 | 禁止直接删除 |
| `C:\ProgramData\NVIDIA Corporation\NVIDIA App\UpdateFramework\ota-artifacts` | NVIDIA 驱动更新包 | 失去已下载安装包，后续可能重新下载 | 需要确认，可清理旧包 |

未知目录只显示容量和路径，不猜测软件，不提供自动删除。

## 6. 保守清理策略

默认可选范围：

- `%LOCALAPPDATA%\Temp` 中最后写入时间超过 7 天、且当前未被占用的文件。
- `%LOCALAPPDATA%\CrashDumps` 中的历史转储。
- 明确识别的应用更新安装包缓存。
- 回收站；默认显示为“需要确认”，执行前再次提示不可恢复。

默认禁止范围：

- 用户的桌面、文档、下载、视频和项目目录。
- WSL/Docker 虚拟磁盘。
- AI 模型、Python 虚拟环境、Node 项目的 `node_modules`。
- 聊天记录、浏览器用户数据和应用数据库。
- `WinSxS`、`Windows\Installer`、驱动存储及其他系统关键目录。
- 任何未被规则库明确允许的路径。

清理引擎采用允许列表：即使界面或报告将某目录标记为“大”，没有安全规则也不能提交给删除引擎。

### 6.1 勾选与一键删除状态规则

- 扫描结果项具有 `Selectable`、`Selected`、`RiskLevel`、`CleanupRuleId` 和 `BlockedReason` 状态。
- 只有 `Selectable=true` 且存在有效 `CleanupRuleId` 的项目才能进入执行清单。
- “一键删除”指一次确认后批量处理已选项目，不表示跳过确认，也不表示删除所有扫描结果。
- 执行前再次验证路径、文件时间、重解析点状态和规则版本；扫描后发生变化的项目会跳过并说明原因。
- 同一路径的父子项目不能重复进入清单，防止重复计算预计释放空间。
- 清理执行期间锁定选择列表，完成或停止后再恢复编辑。
- 清理结果逐项标记“已删除”“部分删除”“已跳过”“失败”，禁止用一个笼统的成功提示掩盖部分失败。

## 7. 权限与安全

- 普通扫描使用当前用户权限。
- 只有执行需要管理员权限的官方系统操作时才请求提权。
- 清理前再次解析并校验绝对路径，拒绝根目录、用户目录根、Windows 根目录、通配符目标和重解析点目标。
- 遇到正在使用或权限不足的文件时跳过并记录，不强制夺取所有权。
- 不结束用户进程，不关闭应用，不修改注册表所有权或 ACL。
- 首版不包含定时清理和后台常驻。

## 8. 架构

- `XDiskInspector.App`：WPF 界面、导航、主题与本地化资源。
- `XDiskInspector.Core`：扫描、容量聚合、风险模型、建议生成。
- `XDiskInspector.Rules`：内置 JSON 目录知识库及匹配器。
- `XDiskInspector.Cleanup`：预览、允许列表校验、执行与结果记录。
- `XDiskInspector.Reporting`：JSON/HTML 报告。
- `XDiskInspector.Tests`：核心逻辑和安全边界测试。

UI 不直接删除文件，只调用清理服务；清理服务只接受扫描产生且通过规则校验的候选项。

## 9. 错误处理

- 无权限：标记并继续。
- 文件在扫描期间消失或变化：跳过或采用最新元数据，不让扫描失败。
- 路径过长：使用现代 .NET 路径 API；仍失败时记录。
- 清理失败：逐项返回原因，不把部分成功报告为全部成功。
- 报告写入失败：允许用户重新选择目录。
- 扫描取消：明确显示“结果不完整”，禁用基于不完整结果的批量清理。

## 10. 测试与验收

采用测试驱动开发。核心测试至少包括：

1. 一级目录容量聚合和大文件排序。
2. 重解析点不被跟随。
3. 无权限、文件消失和取消行为。
4. 已知软件目录识别及未知目录不猜测。
5. 允许列表只接受批准的清理目标。
6. 根目录、用户根目录、Windows 关键目录和重解析点删除请求被拒绝。
7. 预览模式不修改测试文件。
8. 仅删除超过 7 天的临时测试文件。
9. HTML/JSON 报告包含作者、容量、风险、后果和建议。
10. 全选只选中当前范围内的安全建议项。
11. 禁用项不能通过界面状态篡改进入删除清单。
12. 父子路径不会重复计入容量或重复删除。
13. 一键删除只处理最终确认清单，停止后不再开始后续项目。
14. WPF 项目可构建，发布产物可启动。

测试只能在隔离的临时夹具目录中执行，不对真实 C 盘执行删除测试。
