# X C盘巡检官：安全边界

## 1. 清理不是“路径大就删”

所有执行目标必须同时满足：

1. 来自一次完整扫描；
2. `Selectable=true` 且用户已选择；
3. 携带有效 `CleanupRuleId`；
4. 当前规则库版本与扫描时一致；
5. 规则当前仍明确 `AllowCleanup=true`；
6. 绝对路径安全复核通过；
7. 执行前文件时间和重解析点状态仍符合扫描快照；
8. 父子路径去重后进入最终确认清单。

任何一项失败都会跳过并返回具体原因。从磁盘载入的历史 JSON 报告仅供查看，不能直接作为一次新的清理授权来源；要执行清理必须重新扫描当前机器。

## 2. 永久拒绝的自动删除目标

- 磁盘根目录、用户根目录、Windows 根目录。
- 桌面、文档、下载、视频等个人目录**整棵子树**；不仅保护目录根，也保护其任意后代路径。
- `WinSxS`、`Windows\Installer`、`System32`、DriverStore 等系统关键区域。
- `.vhdx` 虚拟磁盘，尤其是 WSL / Docker 数据盘。
- Python `.venv` 与 Node `node_modules`。
- 规则库未明确允许的未知路径。
- 已识别的聊天、浏览器、应用数据库与高风险应用状态目录。
- AI 模型目录默认保留。
- 用户通过安全策略额外指定的禁区同样按整棵目录树保护。

程序不会通过夺取所有权、修改 ACL、结束进程或关闭应用来强行删除文件。

## 3. 规则库安全契约

- 路径同时命中父规则与更具体子规则时，匹配器优先采用**字面路径更具体**的规则；同等具体度才保持 JSON 声明顺序。这允许宽父目录保持“默认保留”，同时让经过审核的细粒度缓存子目录拥有独立策略。
- Rule ID 必须唯一；重复 ID 会在规则库加载时直接失败。
- `AllowCleanup=true` 时必须配置真实的 `CleanupKind`；`AllowCleanup=false` 时不得配置破坏性清理类型。
- `MinAgeDays` 不能为负数；路径模式不能为空。
- 这些配置错误采用 fail-fast，而不是在扫描或删除阶段静默猜测。

## 4. 默认建议清理

- `%LOCALAPPDATA%\Temp`：仅最后写入超过 7 天的文件。
- `%LOCALAPPDATA%\CrashDumps`：历史崩溃转储。

这些文件仍会在执行前复核。如果正在使用、权限不足、扫描后发生变化或变成重解析点，会跳过。

## 5. 需要确认

- Windows 回收站：清空不可恢复，最终窗口要求单独勾选不可恢复确认。产品只把已识别候选所在驱动器根传给 Windows `SHEmptyRecycleBin`；对于 C 盘规则即只请求清空 `C:\` 的回收站，不使用会作用于所有驱动器的空路径调用。
- NVIDIA OTA 更新安装包。
- Bun/npm/pnpm 已识别缓存：删除后依赖可能重新下载。其中 Bun 只允许 `.bun\install\cache`，不会把 `.bun\bin` 或全局安装目录当缓存清理；pnpm 当前 Windows 默认 store 与兼容旧缓存路径均属于“需要确认”，不会被“全选建议项”自动勾选。

## 6. 只提供官方操作指导

- 页面文件：只检测与解释，不进入一键清理。
- Windows 组件存储：只调用 DISM 官方能力，不直接删除 `WinSxS` 或 `Windows\Installer`。
- 已安装软件：只打开 Windows 已安装应用页面。
- WSL / Docker：只提供官方清理、导出、注销或 VHDX 压缩说明，不直接删除虚拟磁盘。

## 7. 测试隔离

所有具有删除行为的自动化测试都在 `%TEMP%\XDiskInspector.Tests\<GUID>` 下创建临时夹具。测试不会向真实 C 盘系统目录提交删除请求。回收站执行测试使用伪服务记录目标驱动器，不调用真实系统回收站 API。

## 8. 真实 Windows 验收前待锁定的边界

以下项目需要在 Windows 环境中先建立 RED 测试，再决定最小生产改动；在取得真实 Runner 证据前不声明为已验证：

1. **个人目录扩展保护**：除桌面、文档、下载、视频外，继续验证“图片、音乐”等用户个人目录子树是否应作为永久禁区。
2. **特殊 Windows 路径语义**：对 NTFS ADS（如 `file.txt:stream`）、UNC/网络路径、Win32 设备路径建立拒绝自动清理的契约，避免规则匹配与实际对象语义不一致。
3. **受限元数据的已知系统项识别**：像 `pagefile.sys` 这类已知高风险路径，即使能枚举但无法读取 `Length/LastWriteTime`，也应在重点项中保留“已识别但容量未知/受限”的证据，而不是静默消失。
4. **异步命令异常边界**：验证 WPF `AsyncRelayCommand` 中未捕获异常不会导致整个 UI 进程异常退出，并据真实测试结果决定统一错误处理策略。

这些项目属于真实机验收后的安全/健壮性门，不会通过降低规则、跳过测试或模拟“已通过”来关闭。
